## Known calibration finding (Phase 8 follow-up)

CloudWatch data-availability log on the first v4 pipeline run revealed that **4 of the new Phase 1 features are not flowing into the pillar calculator**:

```
Pillar v4 data availability (33 evals):
  ma_200=0/33                    ← 0% coverage
  high_52w=0/33                  ← 0% coverage
  sector_rs_20d=0/33             ← 0% coverage
  historical_move_magnitude=0/33 ← 0% coverage
  bb_width_percentile=33/33      ← 100% (working)
  days_to_earnings=9/33          ← 27%
```

Implication:
- **Directional Conviction** (40% exponent): Stage 2 Trend Template (30% subscore weight) and Sector RS (10%) are using fallback values rather than the Phase 1 backfilled data. Composite still computes, but the dominant signal in the dominant pillar is degraded.
- **Move Potential** (35% exponent): Historical post-event move magnitude (20% subscore weight) is not contributing. Falls back to default.
- **Trade Structure** (25% exponent): Unaffected (delta, gamma/theta, DTE, IV percentile, pivot proximity all flowing).

**Hypothesis (to verify in Phase 8):** the FeatureSet wiring path is not pulling these fields into `ScoringContext` at the pillar-compute boundary, even though they're populated in the underlying tables. `bb_width_percentile` working correctly (100%) suggests the price-history table is read but the ma_150/ma_200/52w computations may not be populating those FeatureSet attributes during pipeline scan-time.

The 39 approvals are still meaningful — they passed gates and scored well on the available subscores — but full Sharpshooter scoring is not yet active.

### To restore the saved v4.0.0 policy from this baseline (if active config is later edited and we want to revert to the at-activation snapshot):

The `v4.0.0` policy in DynamoDB is immutable per its hash. If a `v4.0.x` patch is created and activated, reverting is just:

```bash
curl -X POST "https://2nv5mt4d1k.execute-api.us-west-1.amazonaws.com/api/policies/v4.0.0/activate"
```

If the row is somehow lost, re-seed via:

```bash
cd backend && python -c "
import json, requests
p = json.load(open('../baselines/2026-04-17-v4-policy.json'))
r = requests.post(
    'https://2nv5mt4d1k.execute-api.us-west-1.amazonaws.com/api/policies',
    json=p['config'],
)
print(r.status_code, r.text[:200])
"
```
